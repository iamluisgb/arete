Planes y formato del plan

El JSON de un plan, campo a campo, y los planes que vienen con la app. Generado del catálogo real y de un plan de ejemplo.

Un plan es un JSON con cuatro fases. La app valida el fichero entero antes de importarlo: si algo falta, no entra medio plan.

Plan de ejemplo: Areté · Fuerza · Hipertrofia · Definición · 4 fases · la fase 1 trae 6 sesiones.

El esqueleto de un plan, campo a campo:

ClaveQué es
1 … 4Una fase. name y desc para nombrarla, sessions con sus sesiones.
sessionsObjeto: la clave es el nombre de la sesión («Sesión A») y el valor, la lista de ejercicios.
name, sets, repsObligatorios en cada ejercicio: nombre, series y reps.
typeOpcional: main para los principales, assist para accesorios. Solo cambia el orden visual.
repsUn número (5), un rango (8-10), al fallo (F) o un aguante (2min).
_metaOpcional: nombre y descripción que se enseñan al elegir el plan. No entra en el entrenamiento.

Así se ve una fase de verdad, recortada a tres ejercicios:

{
 "1": {
  "name": "Fuerza",
  "desc": "Full-body · 3×5 · Progresión lineal",
  "sessions": {
   "Sesión A": [
    {
     "name": "Sentadilla",
     "sets": 3,
     "reps": "5",
     "type": "main"
    },
    {
     "name": "Press de Banca",
     "sets": 3,
     "reps": "5",
     "type": "main"
    },
    {
     "name": "Peso Muerto",
     "sets": 2,
     "reps": "5",
     "type": "main"
    }
   ]
  }
 }
}

Las reglas que valida la app

  • Cuatro fases con claves 1, 2, 3 y 4. No se pueden saltar ni renumerar.
  • Cada fase necesita name, desc y sessions.
  • Cada sesión es una lista de ejercicios con name, sets y reps. type es opcional (main o assist) y solo cambia el orden visual.
  • reps acepta un número (5), un rango (8-10), al fallo (F) o un aguante (2min, 1min/lado). Un aguante no lleva progresión de carga: no es una serie de reps.
  • Los nombres de ejercicio se cruzan con la ontología: los cinco básicos alimentan el perfil, el resto se entrena sin mover el nivel.
